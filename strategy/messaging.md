# Messaging hierarchy v0.1

All copy below is a **message hypothesis** until tested with real prospects.

## Message architecture

### Core promise
**Возвращайся в работу с контекстом, принимай решения по явным критериям и проверяй приоритеты по фактам.**

### Pillar 1 — Context
**Problem:** information is present but the working thread is lost.  
**Value:** reconstruct the current state, rationale, open loops, and next meaningful step.  
**Proof mechanism:** source links + timeline + confidence/unknowns.

### Pillar 2 — Decisions
**Problem:** options multiply while criteria remain implicit.  
**Value:** compare alternatives against visible constraints and preserve the rationale.  
**Proof mechanism:** criterion matrix + evidence-backed recommendation + decision history.

### Pillar 3 — Time feedback
**Problem:** subjective busyness hides priority drift.  
**Value:** compare where attention actually went with stated goals without a guilt-oriented productivity score.  
**Proof mechanism:** explainable categories + goal/time delta + weekly review.

## Headline candidates to test

1. **Не восстанавливай рабочий контекст заново каждый раз.**
2. **Следующий шаг — с доказательствами, а не по ощущению.**
3. **Проверь, совпадают ли твои приоритеты с тем, куда ушло время.**
4. **Контекст, решения и время — в одной проверяемой истории работы.**

## CTA ladder

Pre-PMF priority:
1. "Пройти 25‑минутное problem interview"
2. "Попробовать concierge context recap"
3. "Разобрать одно реальное решение"
4. "Подключиться к weekly time review"

Do not optimize for "Buy now" until problem/retention evidence exists.
