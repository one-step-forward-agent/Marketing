# Positioning v0.2 — hypothesis, not validated claim

## Positioning chain

### 1. Competitive alternatives
When this product does not exist, the user usually combines:
- search across chats/docs/tasks;
- calendar/task manager;
- generic LLM prompts;
- manual notes or decision matrix;
- automatic time tracker or weekly review.

### 2. Unique attributes we intend to prove
- context assembled from multiple work signals;
- source/data lineage attached to summaries and recommendations;
- explicit decision criteria and rationale history;
- comparison of declared priorities with observed time allocation;
- one continuous evidence model across context, decisions, and retrospectives.

### 3. Value enabled by those attributes
- less repeated reconstruction before meaningful work;
- fewer decisions made from an opaque or forgotten rationale;
- earlier detection of mismatch between stated priorities and actual attention.

### 4. Best-fit segment hypothesis
Start with high-context-switching individual knowledge workers who personally feel the cost of fragmented work evidence and can adopt a tool without enterprise procurement.

### 5. Market frame
Do **not** start by claiming a new category. Test the frame **"evidence-backed work copilot"** against understandable alternatives: AI task manager, AI memory, decision journal, and time tracker.

## Positioning statement

> For knowledge workers who repeatedly lose the thread across projects, one-step-forward-agent is an evidence-backed work copilot that reconstructs context, makes decision criteria explicit, and shows whether time followed priorities. Unlike a standalone task manager, memory tool, or time tracker, it connects those three loops through source-linked evidence.

## What must be true before this becomes external copy

- at least 5 real data points in one coherent segment repeat the same trigger/problem language;
- users demonstrate a current workaround and switching motivation;
- concierge test shows measurable reduction in context-recovery or decision setup time;
- at least some users voluntarily return for the weekly time-feedback loop.
