# 90-day pre-PMF GTM / learning plan

This is not a scale plan. The objective is to find a repeatable segment + trigger + problem before spending on growth.

## Phase 1 — Days 1–30: replace synthetic evidence

**Goal:** 15–20 real interviews across no more than two candidate segments.

Priority segments:
1. product/founder roles with multiple concurrent initiatives;
2. consultants/team leads with frequent handoffs and context switching.

Actions:
- recruit through founder/product communities, professional network, targeted LinkedIn outreach, and adjacent-tool user communities;
- run switch-style interviews focused on a recent concrete episode;
- record current workaround, trigger, cost, frequency, anxiety, and attempted alternatives;
- do not pitch features during the problem interview;
- update JTBD confidence only from empirical sources.

**Exit criterion:** one job/segment combination has ≥5 independent real data points, repeated unprompted language, a concrete workaround, and a believable switching trigger.

## Phase 2 — Days 31–60: concierge proof

Run three narrow experiments rather than building all three JTBD simultaneously.

### Experiment A — context recap
Input: a real user's selected notes/tasks/calendar export.  
Output: source-linked context recap + open loops + proposed next step.  
Metric: self-reported usefulness plus measured minutes avoided before resuming work.

### Experiment B — decision review
Input: one live decision with 2–4 options.  
Output: criteria, evidence table, reversible recommendation.  
Metric: whether user commits to an option and later reopens the rationale.

### Experiment C — weekly time alignment
Input: calendar/activity summary + declared weekly priorities.  
Output: explainable mismatch report.  
Metric: whether user changes next week's plan and returns for a second review.

**Exit criterion:** one experiment demonstrates repeated pull/return behavior in a coherent segment.

## Phase 3 — Days 61–90: message/channel validation

- create one landing page around the winning trigger/JTBD, not the whole platform;
- test 3–4 message variants from `strategy/messaging.md`;
- publish one shareable research insight and one searchable problem explainer per week;
- continue interviews with non-converters;
- introduce a paid pilot only when users request ongoing access or return voluntarily.

## AARRR mapping for this stage

| Stage | Pre-PMF definition | Primary metric |
|---|---|---|
| Acquisition | qualified prospect reaches research/landing flow | qualified conversations/week |
| Activation | user brings one real context/decision/time-review case | % completing first evidence-backed output |
| Retention | user returns with another case without heavy prompting | 2nd-use rate within 14 days |
| Referral | user introduces a peer with the same problem | qualified referred conversations |
| Revenue | user pays for continuing the validated workflow | paid-pilot conversion, not MRR optimization |
